# ExamTrend Analyzer 요구사항 명세서

## 1. 프로젝트 개요

ExamTrend Analyzer는 임의의 기출문제 파일을 분석하여 주요 키워드, 자동 주제 그룹, 유사 문항 후보를 제공하는 범용 데스크톱 분석 프로그램이다.

특정 과목의 고정 단원 사전에 의존하지 않고, 입력된 문항 데이터에서 반복적으로 등장하는 키워드를 기반으로 자동 주제 그룹을 생성한다.

## 2. 시스템 범위

- PDF, Excel, CSV, TXT 파일 로드
- 다중 파일 병합 분석
- 자동 컬럼 매핑
- 키워드 빈도 분석
- N-Gram 분석 (바이그램·트라이그램)
- TF-IDF 기반 키워드 스코어링
- 자동 주제 그룹 분석
- 자동 주제별 출제 비중 분석
- 유사 문항 탐지
- 분석 결과 시각화
- Markdown/TXT 보고서 생성

## 3. 제외 범위

- 특정 과목 전용 고정 단원 분류
- N-Gram 분석 전용 화면 (파이프라인 내부에서는 실행됨)
- TF-IDF 분석 전용 화면 (파이프라인 내부에서는 실행됨)
- 난이도 분석 전용 화면 (파이프라인 내부에서는 실행됨)
- DB 저장 및 불러오기 UI
- 로그인 및 사용자 계정

## 4. 기능 요구사항

### 4.1 파일 처리

FR-001 시스템은 텍스트 기반 PDF 파일을 불러올 수 있어야 한다.  
FR-002 시스템은 Excel(.xlsx, .xls) 파일을 불러올 수 있어야 한다.  
FR-003 시스템은 CSV 파일을 불러올 수 있어야 한다.  
FR-004 시스템은 TXT 파일을 불러올 수 있어야 한다.  
FR-005 시스템은 여러 파일을 동시에 선택할 수 있어야 한다.  
FR-006 시스템은 여러 파일을 하나의 분석 데이터셋으로 병합할 수 있어야 한다.  
FR-007 시스템은 파일명에서 연도, 회차, 시험명 후보를 추출할 수 있어야 한다.  
FR-008 시스템은 원본 파일명을 분석 결과에 보존해야 한다.  
FR-009 시스템은 PDF 페이지 정보를 보존할 수 있어야 한다.  
FR-010 시스템은 손상된 파일에 대해 오류 메시지를 표시해야 한다.

### 4.2 자동 매핑

FR-011 시스템은 question_text, 문제, 문항, 내용 등의 컬럼을 문제 본문 컬럼으로 자동 매핑할 수 있어야 한다.  
FR-012 자동 매핑이 실패한 경우 사용자가 수동 매핑할 수 있어야 한다.  
FR-013 시스템은 필수 컬럼 누락을 감지해야 한다.  
FR-014 시스템은 매핑 적용 상태를 화면에 표시해야 한다.  
FR-015 시스템은 매핑된 데이터를 분석 대상으로 사용해야 한다.

### 4.3 키워드 분석

FR-016 시스템은 문항 텍스트에서 키워드를 추출해야 한다.  
FR-017 시스템은 키워드 빈도 및 문서 빈도를 계산해야 한다.  
FR-018 시스템은 상위 키워드를 정렬하여 표시해야 한다.  
FR-019 시스템은 한글 키워드를 정상적으로 처리해야 한다.  
FR-020 시스템은 키워드 분석 결과를 보고서에 포함해야 한다.

### 4.4 자동 주제 분석

FR-021 시스템은 특정 과목 사전에 의존하지 않고 자동 주제 그룹을 생성해야 한다.  
FR-022 시스템은 전체 문항에서 대표 키워드를 추출해야 한다.  
FR-023 시스템은 대표 키워드를 기반으로 주제 그룹을 구성해야 한다.  
FR-024 시스템은 각 문항을 가장 관련성이 높은 자동 주제에 배정해야 한다.  
FR-025 시스템은 자동 주제별 문항 수를 계산해야 한다.  
FR-026 시스템은 자동 주제별 비율을 계산해야 한다.  
FR-027 시스템은 자동 주제별 대표 키워드를 표시해야 한다.  
FR-028 시스템은 주제 분석 결과를 시각화해야 한다.  
FR-029 시스템은 주제 분석 결과를 보고서에 포함해야 한다.  
FR-030 시스템은 주제에 배정되지 않은 문항을 미분류로 처리해야 한다.

### 4.5 유사 문항 분석

FR-031 시스템은 문항 간 TF-IDF 코사인 유사도를 계산해야 한다.  
FR-032 시스템은 유사도 0.55 이상인 문항 쌍을 표시해야 한다.  
FR-033 시스템은 유사도 점수를 표시해야 한다.  
FR-034 시스템은 문항 원문을 표시해야 한다.  
FR-035 시스템은 문항 출처(파일명)를 표시해야 한다.  
FR-036 시스템은 동일 행 비교를 제외해야 한다.  
FR-037 시스템은 동일 파일 내부 비교를 제외해야 한다.  
FR-038 시스템은 동일 연도와 동일 회차 내부 비교를 제외해야 한다.  
FR-039 시스템은 유사 문항 결과를 보고서에 포함해야 한다.  
FR-040 시스템은 유사 문항 화면을 읽기 전용으로 제공해야 한다.

### 4.6 시각화

FR-041 시스템은 키워드 빈도 막대 차트를 제공해야 한다.  
FR-042 시스템은 자동 주제 비중 파이 차트를 제공해야 한다.  
FR-043 시스템은 한글 폰트가 깨지지 않도록 처리해야 한다.  
FR-044 시스템은 분석 재실행 시 차트를 갱신해야 한다.  
FR-045 시스템은 표시할 데이터가 없을 때 안내 메시지를 보여야 한다.

### 4.7 보고서

FR-046 시스템은 Markdown 보고서를 생성할 수 있어야 한다.  
FR-047 시스템은 TXT 보고서를 저장할 수 있어야 한다.  
FR-048 보고서에는 분석 개요(문항 수, 파일명)가 포함되어야 한다.  
FR-049 보고서에는 키워드 분석 결과가 포함되어야 한다.  
FR-050 보고서에는 자동 주제 분석 결과(비중, 대표 키워드)가 포함되어야 한다.  
FR-051 보고서에는 유사 문항 분석 결과가 포함되어야 한다.  
FR-052 보고서에는 데이터 검증 이슈가 포함되어야 한다.

## 5. 비기능 요구사항

NFR-001 시스템은 Windows 환경에서 실행 가능해야 한다.  
NFR-002 시스템은 PySide6 기반 GUI를 제공해야 한다.  
NFR-003 시스템은 1000개 이상의 문항을 처리할 수 있어야 한다.  
NFR-004 시스템은 분석 중 GUI 프리징을 최소화해야 한다 (QThreadPool 활용).  
NFR-005 시스템은 UTF-8 인코딩을 사용해야 한다.  
NFR-006 시스템은 한글 UI를 제공해야 한다.  
NFR-007 시스템은 모듈화된 계층 구조를 유지해야 한다.  
NFR-008 시스템은 분석 로직과 UI 로직을 분리해야 한다.  
NFR-009 시스템은 오류 발생 시 사용자에게 명확한 메시지를 제공해야 한다.  
NFR-010 시스템은 GitHub 업로드 및 협업에 적합한 구조를 가져야 한다.  
NFR-011 시스템은 Kiwipiepy 미설치 환경에서도 정규식 폴백으로 동작해야 한다.
