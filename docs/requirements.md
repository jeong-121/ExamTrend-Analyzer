# 요구사항 명세서

## 1. 문서 개요

본 문서는 ExamTrend-Analyzer 프로젝트의 기능 요구사항과 비기능 요구사항을 상세히 정의한다. 시스템은 기출문제 데이터를 입력받아 전처리, 키워드 분석, 출제 경향 분석, 난이도 분석, 유사 문항 탐지, 시각화, 보고서 생성을 수행하는 PySide6 기반 데스크톱 애플리케이션이다.

## 2. 기능 요구사항

### 2.1. 데이터 파일 입력

- FR-001: 사용자는 CSV 형식의 기출문제 데이터를 불러올 수 있어야 한다.
- FR-002: 사용자는 XLSX/XLS 형식의 기출문제 데이터를 불러올 수 있어야 한다.
- FR-003: 사용자는 PDF 형식의 기출문제 파일을 불러올 수 있어야 한다.
- FR-004: 사용자는 TXT 형식의 텍스트 파일을 불러올 수 있어야 한다.
- FR-005: 시스템은 여러 파일을 동시에 선택하여 병합 로딩할 수 있어야 한다.
- FR-006: 시스템은 파일 선택 대화상자를 통해 분석 대상 파일을 선택할 수 있어야 한다.
- FR-007: 시스템은 파일 확장자가 지원 대상인지 확인해야 한다.
- FR-008: 시스템은 지원하지 않는 파일 형식이 입력되면 오류 메시지를 표시해야 한다.
- FR-009: 시스템은 빈 파일을 불러올 경우 사용자에게 경고해야 한다.
- FR-010: 시스템은 손상된 파일을 불러올 경우 예외를 처리해야 한다.
- FR-011: 시스템은 대용량 파일 로딩 시 UI가 멈추지 않도록 별도 스레드로 처리해야 한다.
- FR-012: 시스템은 파일 로딩 완료 후 데이터 행 수를 표시해야 한다.
- FR-013: 시스템은 필수 열이 누락된 경우 사용자에게 누락 항목을 안내해야 한다.
- FR-014: 시스템은 UTF-8, UTF-8 BOM, CP949, EUC-KR 인코딩 CSV 파일을 자동 감지하여 읽을 수 있어야 한다.
- FR-015: 시스템은 인코딩 판별 실패 시 사용자에게 오류 정보를 제공해야 한다.
- FR-016: 시스템은 Excel 파일의 첫 번째 시트를 기본 분석 대상으로 불러올 수 있어야 한다.
- FR-017: 시스템은 PDF 파일에서 텍스트 기반 문항 본문을 추출할 수 있어야 한다.
- FR-018: 시스템은 PDF에서 문항 번호 기준으로 개별 문항을 분리할 수 있어야 한다.
- FR-019: 시스템은 PDF 문항 데이터에 원본 파일명과 페이지 정보를 포함해야 한다.
- FR-020: 시스템은 PDF 텍스트 추출 실패 시 스캔 PDF임을 안내해야 한다.

### 2.2. 파일명 메타데이터 추출

- FR-021: 시스템은 파일명에서 연도 정보를 자동으로 추출할 수 있어야 한다.
- FR-022: 시스템은 파일명에서 회차(n회, n차) 정보를 자동으로 추출할 수 있어야 한다.
- FR-023: 시스템은 파일명에서 시험 월(n월) 정보를 자동으로 추출할 수 있어야 한다.
- FR-024: 시스템은 파일명에서 시험명(수능, 모의고사, 학력평가 등) 패턴을 인식할 수 있어야 한다.
- FR-025: 시스템은 추출된 파일명 메타데이터를 데이터프레임 컬럼(exam_round, month, exam_name)에 자동 부여해야 한다.
- FR-026: 시스템은 파일명에서 메타데이터를 추출하지 못한 경우 해당 컬럼을 None으로 유지해야 한다.
- FR-027: 시스템은 source_file 컬럼에 원본 파일명을 자동으로 부여해야 한다.
- FR-028: 시스템은 여러 파일 병합 시 각 파일의 source_file 메타데이터를 보존해야 한다.

### 2.3. 데이터 구조 및 필드 매핑

- FR-029: 시스템은 question_text(문제 본문) 필드를 필수 표준 필드로 관리해야 한다.
- FR-030: 시스템은 year, chapter, question_type, difficulty, answer, explanation, source, subject, exam_name, question_id 등 선택 표준 필드를 관리해야 한다.
- FR-031: 시스템은 exam_round, month 필드를 추가 표준 필드로 관리해야 한다.
- FR-032: 시스템은 파일 로딩 시 열 이름 별칭(alias)을 기반으로 표준 필드 자동 매핑을 시도해야 한다.
- FR-033: 시스템은 자동 매핑 성공 여부를 UI에 표시해야 한다.
- FR-034: 자동 매핑이 불가할 경우 시스템은 수동 매핑 다이얼로그를 제공해야 한다.
- FR-035: 수동 매핑 다이얼로그에서 사용자는 원본 컬럼을 표준 필드에 연결할 수 있어야 한다.
- FR-036: 시스템은 수동 매핑 시 필수 필드가 누락된 경우 적용을 거부하고 경고를 표시해야 한다.
- FR-037: 시스템은 동일 표준 필드에 중복 매핑이 발생하면 접미사로 구분해야 한다.
- FR-038: 시스템은 별칭(alias) 사전에 없는 열은 원본 이름을 유지해야 한다.
- FR-039: 시스템은 별칭 사전을 확장 가능한 구조로 관리해야 한다.
- FR-040: 시스템은 필드 매핑 상태(자동/수동)를 대시보드에 표시해야 한다.

### 2.4. 데이터 검증

- FR-041: 시스템은 파일 로딩 후 데이터 유효성 검사를 수행해야 한다.
- FR-042: 시스템은 데이터셋이 비어 있을 경우 오류(error) 수준으로 감지해야 한다.
- FR-043: 시스템은 필수 컬럼(question_text) 누락을 오류 수준으로 감지해야 한다.
- FR-044: 시스템은 year 또는 question_text가 비어 있는 행을 오류 수준으로 감지해야 한다.
- FR-045: 시스템은 chapter, question_type, difficulty, answer 값이 비어 있는 행을 경고(warning) 수준으로 감지해야 한다.
- FR-046: 시스템은 연도 값이 허용 범위(1990~2100) 밖이거나 비정상적인 경우 경고해야 한다.
- FR-047: 시스템은 문제 본문 길이가 1~4자인 경우(지나치게 짧음) 경고해야 한다.
- FR-048: 시스템은 문제 본문이 5000자를 초과하는 경우(지나치게 김) 경고해야 한다.
- FR-049: 시스템은 완전히 동일한 문제 본문을 가진 문항을 중복으로 경고해야 한다.
- FR-050: 시스템은 유사도 0.92 이상인 문항을 유사 문항 후보로 경고해야 한다.
- FR-051: 시스템은 정의되지 않은 난이도 값을 경고해야 한다.
- FR-052: 시스템은 정답 값이 누락된 행을 경고해야 한다.
- FR-053: 시스템은 검증 이슈를 level(error/warning/info)과 code 기준으로 구분해야 한다.
- FR-054: 시스템은 검증 결과를 분석 화면의 "검증/경고" 탭 표로 제공해야 한다.
- FR-055: 시스템은 검증 오류(error)가 있을 경우 분석 파이프라인을 중단해야 한다.
- FR-056: 시스템은 검증 경고(warning)는 사용자에게 표시하되 분석을 진행해야 한다.
- FR-057: 시스템은 검증 결과에 행 인덱스와 컬럼명을 함께 제공해야 한다.
- FR-058: 시스템은 키워드 기반 단원 자동 분류 적용 시 info 수준 이슈로 안내해야 한다.
- FR-059: 시스템은 검증 실패 시 원본 데이터를 변경하지 않아야 한다.
- FR-060: 시스템은 대규모 데이터에서 유사 문항 검사 쌍 수를 제한(최대 3,000쌍)하여 성능을 유지해야 한다.

### 2.5. 전처리

- FR-061: 시스템은 문제 본문에서 앞뒤 공백을 제거해야 한다.
- FR-062: 시스템은 연속된 공백을 하나의 공백으로 정규화해야 한다.
- FR-063: 시스템은 한글, 영문, 숫자 이외의 특수문자를 공백으로 치환해야 한다.
- FR-064: 시스템은 영문 토큰에 붙은 한글 조사를 분리하여 제거할 수 있어야 한다.
- FR-065: 시스템은 기본 불용어 사전을 내장하여 제공해야 한다.
- FR-066: 시스템은 조사, 어미, 문제 지시문 표현 등 분석 가치가 낮은 어휘를 불용어로 처리해야 한다.
- FR-067: 시스템은 여러 문항을 일괄 전처리할 수 있어야 한다.
- FR-068: 시스템은 원본 데이터를 보존하고 전처리 결과를 별도로 관리해야 한다.
- FR-069: 시스템은 Kiwipiepy(한국어 형태소 분석기)를 사용할 수 있을 때 자동 적용해야 한다.
- FR-070: 시스템은 Kiwipiepy가 없을 경우 정규식 기반 폴백 토크나이저를 사용해야 한다.
- FR-071: 시스템은 Kiwi 사용 시 명사(N 태그) 및 외래어(SL) 품사만 추출해야 한다.
- FR-072: 시스템은 한글 토큰에서 조사 및 어미 접미사를 제거하는 규칙을 적용해야 한다.
- FR-073: 시스템은 영문 토큰을 대문자로 정규화해야 한다.
- FR-074: 시스템은 최소 토큰 길이(기본 2자 이상)를 기준으로 단일 문자 토큰을 필터링해야 한다.
- FR-075: 시스템은 순수 숫자 토큰을 키워드 분석에서 제외해야 한다.
- FR-076: 시스템은 자모 단독 문자(ㄱ~ㅎ, ㅏ~ㅣ)를 필터링해야 한다.
- FR-077: 시스템은 사용자 정의 불용어를 추가할 수 있는 구조여야 한다.
- FR-078: 시스템은 None 입력을 안전하게 처리하여 빈 토큰 목록을 반환해야 한다.
- FR-079: 시스템은 nbsp 등 비표준 공백 문자를 정규화해야 한다.
- FR-080: 시스템은 전처리 결과 토큰 목록을 하위 분석 모듈에 전달해야 한다.

### 2.6. 토큰화 및 키워드 추출

- FR-081: 시스템은 문제 본문을 토큰 단위로 분리할 수 있어야 한다.
- FR-082: 시스템은 unigram 키워드 빈도를 계산할 수 있어야 한다.
- FR-083: 시스템은 bigram(2-gram) 키워드 빈도를 계산할 수 있어야 한다.
- FR-084: 시스템은 trigram(3-gram) 키워드 빈도를 계산할 수 있어야 한다.
- FR-085: 시스템은 키워드별 전체 등장 횟수(frequency)를 계산해야 한다.
- FR-086: 시스템은 키워드별 등장 문항 수(document_frequency)를 계산해야 한다.
- FR-087: 시스템은 TF-IDF 기반 키워드 점수를 계산할 수 있어야 한다.
- FR-088: 시스템은 상위 N개 키워드를 표시할 수 있어야 한다 (기본값: 상위 50개).
- FR-089: 시스템은 키워드 분석 결과를 키워드/빈도/문서빈도 형태의 표로 제공해야 한다.
- FR-090: 시스템은 키워드 분석 결과를 분석 화면의 "키워드" 탭에 표시해야 한다.
- FR-091: 시스템은 상승 추세 키워드를 최근 N개 연도와 이전 연도 평균 비교로 계산해야 한다.
- FR-092: 시스템은 반복 출제 키워드를 연도 수, 최장 연속 출제 streak, 총 출현 횟수 기준으로 계산해야 한다.
- FR-093: 시스템은 키워드별 출현 연도 목록을 제공할 수 있어야 한다.
- FR-094: 시스템은 최장 연속 출제 기간(consecutive streak)을 키워드별로 계산해야 한다.
- FR-095: 시스템은 연도별 상위 키워드 빈도 매트릭스를 제공해야 한다.
- FR-096: 시스템은 n-gram 분석에서 n 값을 호출 시 지정할 수 있어야 한다.
- FR-097: 시스템은 상위 키워드 막대 차트(수평)를 시각화 탭에 표시해야 한다.
- FR-098: 시스템은 분석에 실패해도 빈 결과를 반환하고 오류를 상위로 전파하지 않아야 한다.
- FR-099: 시스템은 sklearn의 TfidfVectorizer를 활용하여 TF-IDF를 계산해야 한다.
- FR-100: 시스템은 빈 텍스트가 입력된 경우 해당 문항을 TF-IDF 계산에서 제외해야 한다.

### 2.7. 출제 경향 분석

- FR-101: 시스템은 연도별 문제 수를 계산해야 한다.
- FR-102: 시스템은 단원별 문제 수 및 출제 비율을 계산해야 한다.
- FR-103: 시스템은 연도별 단원 출제 분포를 계산해야 한다.
- FR-104: 시스템은 단원별 출제 분포를 파이 차트로 시각화해야 한다.
- FR-105: 시스템은 단원 정보가 없는 경우 키워드 기반 자동 단원 분류기를 적용해야 한다.
- FR-106: 시스템은 chapter_auto 컬럼이 이미 존재하는 경우 재분류 없이 사용해야 한다.
- FR-107: 시스템은 chapter 컬럼, chapter_auto 컬럼, 키워드 자동 분류의 우선순위를 순서대로 적용해야 한다.
- FR-108: 시스템은 단원 분류 출처(provided/provided_auto/keyword_auto/none)를 분석 결과에 포함해야 한다.
- FR-109: 시스템은 최근 출제 빈도가 증가한 키워드를 식별해야 한다.
- FR-110: 시스템은 반복 출제된 개념 키워드를 연도 수 및 연속 출제 streak 기준으로 식별해야 한다.
- FR-111: 시스템은 장기간 미출제 단원을 식별할 수 있는 구조를 가져야 한다.
- FR-112: 시스템은 분석 실행 상태(analysis_status)를 항목별로 기록해야 한다.
- FR-113: 시스템은 건너뛴 분석 항목(skipped_analyses)을 목록으로 제공해야 한다.
- FR-114: 시스템은 단원 분포 결과를 단원별 문항 수와 비율(%)로 제공해야 한다.
- FR-115: 시스템은 분석 결과를 보고서 생성 기능에 전달할 수 있어야 한다.
- FR-116: 시스템은 분석 결과 요약 문장을 분석 화면의 "요약" 탭에 표시해야 한다.
